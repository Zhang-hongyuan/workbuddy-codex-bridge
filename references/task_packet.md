# REQUEST 任务包模板（六段式）

> 用法：复制本骨架为 `<目标目录>/REQUEST_<主题>.md`（目标目录=Codex 动手/审计的目录，与 dispatch `--cwd` 货架锚点相互独立），填实后 dispatch 指引 Codex 读取。
> 约束段必须选定一种交付模式，并保留凭据与用户记忆文件红线；不能同时要求分支 commit 和原目录直改。

```markdown
# REQUEST：<任务标题>（<日期 YYYY-MM-DD>）

## 1. 背景
<为什么有这个任务，三两句话。相关的文件/模块/历史决策，给路径不给口述。>

本单基线 commit：<WorkBuddy 派单时填入第 0 步探针得到的完整哈希；模式B 填"授权直改，基线 <哈希或无>"；纯只读单可填"豁免">。

## 2. 目标
<完成什么，可判定的终态。一句话能验证的那种。>

## 3. 范围
- 做：<明确边界内>
- 不做：<明确边界外，防止自由发挥>

## 4. 约束（红线，必备）
1. 交付模式：<A 或 B，只保留适用条款>。
   - 模式A（代码修改默认）：在同一仓库 `codex/<任务名>` 分支及原目录外的独立 worktree 修改并 commit；原目录不切分支、不编辑、不暂存。写入前展示原目录/worktree/分支/完整基线提交号。WorkBuddy 终审、用户最终确认后由 WorkBuddy 合入，Codex 禁止合主干。
   - 模式B：代码任务仅在用户明确授权原目录直改、且无适用项目约束冲突时使用；非代码文件任务可在本单范围使用。授权目录为 <绝对路径>，授权依据为 <用户原文/日期>。每个既有文件修改前先 `cp <文件> <文件>.bak-<时间戳>`；WorkBuddy 验收及用户确认前禁止删备份，新建文件无需备份。本模式不要求分支 commit。
2. 不读取、不复制、不输出任何密钥/凭据/Token 类文件内容。
3. 用户记忆文件只读；日志类文件不追加。
4. <本单特有约束，如：只读审查不写文件 / 允许跑测试不许改测试>

## 5. 产物要求
- <产物1：路径+形态，如 `docs/review_<主题>.md`，含 findings 列表>
- <产物2：模式A填分支/基线及结果 commit；模式B填实际修改/备份路径；只读审查填报告，不要求 commit>

## 6. 验收标准
- [ ] <可勾验的标准1>
- [ ] <可勾验的标准2>
- [ ] 最终回复自报产物清单：每项产物的路径/行数（文件）或 commit hash（代码）/执行过的工具
```

## 填写纪律

- **给路径不给口述**：背景里引用代码/文档一律写绝对路径或 repo 相对路径，Codex 自己会读；别把几百行代码贴进背景。
- **目标要可判定**：写"修好后 `pytest tests/x.py` 全绿"，不写"优化一下质量"。
- **验收标准即对账清单**：我方回收时逐条核验，勾不齐=未完工，在原任务打回；原生任务用 App 输入，后台任务才用对应后端的 steer。
- **基线必填**：基线 commit 是收单 `git diff` 对账的锚点；纯只读单可按第 0 步明确记录"只读豁免"，不要求建基线或 commit。除该已记录的豁免外，WorkBuddy 派单前未做第 0 步探针的任务包视为废单，Codex 有权拒接。
